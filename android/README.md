# Изучение Библии · Android

Нативное Kotlin-приложение без WebView. Основано на [Slakwik/bible-learning](https://github.com/Slakwik/bible-learning), сервер ответов — существующий Firebase-проект сайта. Версия [0.6.0](https://github.com/Slakwik/learning-bible-app/releases/tag/v0.6.0). Сборка и автоматические проверки завершены; полная ручная приёмка продолжается.

## Интерфейс

- **Курсы:** карточки с русскими названиями, поиск по курсу/названию урока/отрывку, продолжение последнего урока.
- **Класс:** доступные классы, ведущий, расписание и курсы программы. У ведущего — ученики, их курсы и ответы класса только для просмотра. Личные ответы учеников не показываются.
- **Урок:** Markdown/HTML выводится нативным TextView через Markwon. Вопросы остаются на своих местах между пояснениями, включая подпункты q3a/q3b. Автосохранение при вводе, отдельная кнопка синхронизации.
- **Настройки:** отдельный экран; выборы сохраняются между запусками.

Визуальная система: тёплый светлый фон #F8F7F2, белые карточки радиусом 22dp, тёмно-зелёные действия #285B42, книжный текст 18sp по умолчанию. В тёмной теме — фон #151A18 и светлый шалфейный акцент #A7D4B5. Основной/вторичный текст и кнопки проверяются на контраст 4.5:1. Системный масштаб шрифта не отключается. Минимальная высота основных кнопок — 48dp. Отступы учитывают системные панели и клавиатуру; принудительной портретной ориентации нет.

Это описание реализованных компонентов, не подтверждение визуального теста на Galaxy S9.

## Хранение и синхронизация

SQLite находится в закрытой папке приложения, ключ записи — (uid, class_id, slug). Миграция сохраняет прежние записи личными; пустой class_id обозначает личное изучение. Чтение/редактирование гостя отделено от каждого аккаунта. Старый SharedPreferences не удаляется и не назначается автоматически вошедшему пользователю.

Каждая запись содержит тексты, базовую серверную версию, ревизию, признак изменений и конфликтную копию. Изменения каждого поля последовательно сохраняются на локальной I/O-очереди. При подтверждении отправки локальная копия не удаляется; изменения, введённые во время отправки, остаются в очереди.

Синхронизация читает сервер, а затем проверяет изменённые документы Firestore-транзакциями:

1. Если менялось только одно устройство, берётся его изменение.
2. Изменения разных вопросов объединяются.
3. Если одно поле изменилось по-разному, сервер не перезаписывается, обе версии остаются для явного выбора.
4. Очистка ответа считается изменением, а не отсутствием данных.
5. Ошибка сети/прав не помечает записи отправленными.

Личное изучение использует answers/{uid}_{slug}; урок класса — classAnswers/{classId}_{uid}_{slug} с дополнительным полем _class. Поля q*, _uid, _lesson, _savedAt сохранены. Классный редактор проверяет доступ и загружает серверную версию перед открытием; без подтверждённого доступа он не позволяет редактировать. Архив и отсутствие членства означают только чтение. Черновики недоступных классов сохраняются для экспорта. Просмотр чужих ответов ведущим требует свежей проверки роли и не сохраняется в локальную базу. Приложение не меняет Firestore Rules и не создаёт аккаунты учеников.

Дисковый кэш Firestore отключён. Приложение отправляет изменения только онлайн-транзакциями, не обычными отложенными set-записями: сохранение без сети принадлежит SQLite. Переключатели сети проверяются до отправки. Уже начатый сетевой запрос может завершиться после выключения фонового режима. Фоновая синхронизация откладывается при открытом редакторе, а читалка ждёт завершения уже начатой синхронизации перед отображением версии.

Ограничение существующего сайта: его JS по-прежнему записывает весь документ без проверки версии. Приложение обнаруживает уже случившиеся изменения сайта, но не может предотвратить более позднюю перезапись из старой вкладки сайта. Полная защита всех клиентов потребует согласованной доработки веб-редактора.

[Firestore transactions](https://firebase.google.com/docs/firestore/manage-data/transactions), [WorkManager scheduling](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work), [Android window insets](https://developer.android.com/develop/ui/views/layout/edge-to-edge).

## Каталог уроков

Все 227 исходных уроков входят в APK. Ручное обновление загружает https://learning.spbchurch.ru/assets/mobile-catalog.json по HTTPS, проверяет схему, уникальность slug/вопросов, ограничение размера 8 MiB, а затем атомарно заменяет предыдущий пакет. Ошибка оставляет старые материалы доступными.

Шаблон feed добавлен в assets/mobile-catalog.json. **Для сетевого обновления его ещё нужно опубликовать обычной Jekyll-сборкой сайта.** Само добавление в Android-репозиторий не публикует файл на сервере. До этого встроенные уроки работают офлайн; кнопка обновления сообщит о недоступном каталоге. Обновляется полный каталог, а не выбранные курсы по отдельности.

## Проверки и сборка

Требуются Java 17, Gradle 8.10.2 и Android SDK 35. Версии AGP/Kotlin зафиксированы в build.gradle. Gradle Wrapper ещё не добавлен: его бинарный JAR не генерировался и не скачивался в этой среде.

Из корня репозитория:

~~~sh
node --test android/tools/check-source.cjs
cd android
gradle --no-daemon testDebugUnitTest lintDebug assembleDebug
~~~

Offline-проверки извлекают регулярное выражение парсера из Kotlin-кода и сверяют все 4258 полей ответов с источником. Также проверяют метаданные, контраст, манифест и ключевые структурные ограничения. Это не компиляция Kotlin.

В app/src/test добавлены 22 JUnit/Robolectric-сценария: слияние, очистка поля, подпункты вопросов, Unicode, изоляция аккаунтов, позднее чтение, редактирование во время отправки, сохранение копий, явное разрешение конфликта и парсер.

**Сборка проверена 15.09.2026 в [GitHub Actions](https://github.com/Slakwik/learning-bible-app/actions/runs/35009004647):** 7 offline-проверок и все 22 JUnit/Robolectric-теста прошли; `lintDebug` завершился без ошибок (12 предупреждений), `assembleDebug` создал APK версии 0.2.0-preview. В APK проверено наличие всех 227 уроков. Артефакты запуска: `bible-learning-debug-apk` и `android-check-reports`. Проверка на физическом устройстве и вход настоящим аккаунтом ещё не выполнены.

Для воспроизводимой сборки исправлены установка SDK в CI (только `platform-tools` вместо недоступного пакета `tools`) и идентификатор прокрутки (`R.id.screen_scroll` вместо числовой константы).

## Релизы и подпись

Debug APK — только тестовый артефакт. Ключ debug на разных CI-машинах может меняться, поэтому он не годится для стабильных обновлений поверх установленного приложения.

Теги v* публикуют только подписанный предварительный release APK после успешных проверок. Нужны GitHub Secrets:

- ANDROID_KEYSTORE_BASE64 — постоянный keystore в base64.
- ANDROID_STORE_PASSWORD.
- ANDROID_KEY_ALIAS.
- ANDROID_KEY_PASSWORD.

Ключ должен храниться у владельца проекта и использоваться для следующих обновлений. Здесь ключ не создан; workflow без него останавливается, а не выпускает случайно подписанный APK. Перед обычным релизом изменить статус preview и выполнить проверки на устройстве.

Firebase пока использует публичную конфигурацию исходного веб-проекта через FirebaseOptions. Вход настоящим аккаунтом не проверялся; ограничения API-ключа/App Check и регистрация Android-приложения требуют отдельной проверки владельцем Firebase. Секретов администратора в коде нет.

## Ручная приёмка на Galaxy S9

1. Светлая/тёмная/бумажная темы; системный шрифт 100%, 130%, 200%; вертикально и горизонтально.
2. Длинные названия курсов, клавиатура у последнего вопроса, большой ответ, TalkBack.
3. Полётный режим: чтение и ввод; закрыть процесс, открыть и проверить черновик.
4. Аккаунты A/B и гость: ответы и закладки не переходят между ними.
5. Синхронизация, отключение сети посередине, повторная отправка без потери черновиков.
6. Разные и одинаковые поля на сайте/телефоне; очистка последнего ответа; обе кнопки выбора версии.
7. Экспорт и чтение JSON; отмена выбора файла; удаление обновлений не затрагивает ответы.
8. Проверить поведение энергосбережения Samsung: фоновый запуск может задерживаться, ручной остаётся доступным.
9. Обновление APK тем же ключом поверх предыдущей сборки без удаления данных.

Локальные файлы приложения не зашифрованы отдельным ключом приложения; используется изоляция Android. Автобэкап отключён, экспорт сознательный и незашифрованный. Удаление приложения/его данных удаляет несинхронизированные локальные черновики.

## Доступ к курсам (0.3.1-preview)

Без авторизации доступны только названия и описания курсов. После входа каталог показывает вводный текст урока до первого вопроса, без вопросов и ответов. Полные уроки и работа с ответами доступны только в классе; ведущие сохраняют просмотр своих учеников. Синхронизация отправляет только ответы классов. Старые личные и гостевые записи остаются в локальном хранилище и экспорте, автоматически в классы не переносятся.
