# Сбой открытия формы входа на Android 10

Дата: 15.09.2026. Устройство: Samsung Galaxy S9+ (SM-G965F), Android 10. Исходная версия: 0.2.0-preview.

## Причина

В журнале Android зарегистрирован `ClassCastException` при открытии `LoginActivity`: `ViewGroup.LayoutParams` нельзя привести к `LinearLayout.LayoutParams`. Сбой происходил в `TextInputLayout.updateInputLayoutMargins`, вызванном из общего помощника `input` в `Ui.kt`. До запроса аутентификации выполнение не доходило.

## Исправления

- Для дочернего поля `TextInputLayout` передаются `LinearLayout.LayoutParams`.
- Добавлен `LoginActivityTest`: создание настоящей формы с полями email/пароля на API 29 и 35, без Firebase-сессии и отправки данных.
- Тест API 35 дополнительно выявил обращение к контроллеру системных панелей до создания decor view. Настройка панелей перенесена после `setContentView`.

## Проверка на телефоне

- Собрана и установлена отдельная копия `ru.spbchurch.biblelearning.diagnostic`, название «Библия · Проверка», из workflow `Android device check`, run 35016407244.
- Через интерфейс открыты каталог, настройки и форма входа. Форма отобразилась, процесс продолжил работать.
- Эта копия включает исправление параметров разметки; более позднее исправление инициализации панелей для API 35 проверяется отдельно в CI.
- Исходное приложение и его данные не удалялись. Диагностическая копия имеет отдельное локальное хранилище; фоновая синхронизация по умолчанию выключена.
- Вход с настоящими данными выполняет владелец телефона; результат записывается отдельно после проверки. Пароли, токены и пользовательские ответы в отчёт не включаются.

## Ограничение обновления

Опубликованный preview подписан временным debug-ключом CI. Новая сборка не считается совместимым обновлением до проверки сертификата. Диагностический package suffix позволяет проверить исправление без удаления исходного приложения и его черновиков. Это не постоянная схема выпуска обновлений.
