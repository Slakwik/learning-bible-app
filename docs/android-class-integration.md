# Совместимость Android с учебными классами сайта

## Результат проверки 15.09.2026

В авторизованном интерфейсе сайта подтверждено: отправленный с Android ответ отображается в «Мои ответы», а соответствующий урок внутри класса имеет отдельные пустые поля. Проверка выполнялась чтением, без переноса или сохранения ответов. Персональные данные и содержание ответов здесь не сохраняются.

Это функциональный пробел Android-клиента: его успешная отправка личного ответа не означает отправку в класс. Счётчик `sent` в `Sync.kt` считает успешно отправленные документы уроков, а не отдельные вопросы.

## Устройство сайта

| Объект | Назначение |
| --- | --- |
| `users/{uid}` | Профиль и роль: user, leader, admin |
| `classes/{classId}` | Ведущий, участники, упорядоченная программа, расписание, архив |
| `answers/{uid}_{lessonSlug}` | Личные ответы, используемые текущим Android-клиентом |
| `classAnswers/{classId}_{uid}_{lessonSlug}` | Ответы конкретного участника конкретного класса |
| `announcements` | Общие объявления |
| `classes/{classId}/announcements` | Объявления класса |
| `classes/{classId}/invitations` | Приглашения участников |

Урок сайта с `?class=...` читает и сохраняет `classAnswers`; без параметра — `answers`. Один и тот же урок может иметь независимые ответы в личном изучении и в нескольких классах. Программа класса задаётся списком lessonSlugs и не обязана совпадать с одним курсом.

Роли и ограничения ниже подтверждены исходниками сайта в репозитории; интерфейсы руководителя и администратора под их аккаунтами в этой проверке не открывались:

- Ученик видит свои классы и собственные ответы класса.
- Ведущий управляет назначенными ему классами и читает ответы участников этих классов.
- Администратор управляет классами и ведущими.
- Запись ответа класса требует членства, урока в программе и неархивного класса; роль руководителя сама по себе не подменяет членство для записи ответа ученика.
- Права проверяются Firestore Rules, а не только видимостью кнопок. Личные и классные ответы имеют разные правила доступа.

## Следующая функциональная доработка

1. Загрузить профиль и доступные классы; добавить явный выбор «Личное изучение / Мои классы».
2. Показывать ведущего, расписание и программу выбранного класса; открывать урок с неизменяемым контекстом classId.
3. Расширить локальное хранение, закладки, позицию чтения и очередь синхронизации контекстом класса; миграция оставляет существующие записи личными.
4. Синхронизировать ответы класса с `classAnswers`, сохраняя слияние, конфликтные версии и обработку отказа доступа.
5. Отображать место назначения ответа и результат: «Личные уроки: … / Уроки класса: …». Не создавать впечатление, что личная отправка доступна ведущему класса.
6. Предложить отдельное явное действие копирования личного ответа в выбранный класс с предпросмотром конфликтов. Автоматически переносить или дублировать личные ответы нельзя: это меняет круг читателей.
7. Проверить цепочку Android → урок класса на сайте → просмотр ведущим и обратную синхронизацию, затем два класса с одним уроком, архивирование и отзыв доступа.

Критерий приёмки: ответ, введённый именно в контексте класса на телефоне, появляется в том же классе на сайте; личные ответы остаются независимыми. Это приоритетная совместимость для группового использования, а не необязательное расширение после оформления.

## Реализовано в 0.3.0-preview

Раздел «Моё» заменён на «Класс». Доступны классы аккаунта, курсы их программы, личные ответы участника внутри класса и их синхронизация. Ведущий/администратор может открыть список учеников и просматривать их ответы по курсам своего доступного класса. Просмотр ответов ученика не редактирует их и не сохраняет в локальную базу ведущего.

SQLite мигрирует на ключ `(uid, class_id, slug)`, сохраняя прежние записи личными. Экспорт содержит оба контекста отдельно. Для открытия класса требуется серверная проверка доступа; при ошибке сети редактор не разрешает запись поверх неизвестной версии. Личные ответы автоматически в классы не переносятся. Объявления, управление составом и копирование личных ответов в класс не входят в этот выпуск.

Проверка: 30 JVM-тестов и 29 тестов Firestore Rules/транзакций прошли. Полная ручная приёмка ведущего и обмена с сайтом остаётся отдельным шагом.
