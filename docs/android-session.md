# Сохранение входа на Android

Firebase Auth сохраняет сессию и обновляет токены. Приложение вызывает signOut только после подтверждения выхода в настройках. Очистка загруженного каталога и сброс оформления не очищают авторизацию. Пароль приложение не записывает в настройки, SQLite или экспорт.

В 0.3.2-preview форма входа запоминает email успешного входа; постоянные ID и подсказки полей помогают Android Autofill распознавать аккаунт. После успешного входа AutofillManager.commit вызывается до очистки поля пароля. Сохранение пароля предлагает системный менеджер, если он включён пользователем.

## Подпись и обновления

С 0.3.2-preview основной и диагностический workflow используют постоянный ключ предварительных APK из GitHub Secret ANDROID_PREVIEW_KEYSTORE_BASE64. Резервная копия ключа находится вне репозитория в локальном каталоге ~/.local/share/bible-learning/signing/preview.jks. Ключ нельзя публиковать. Стандартный пароль debug-хранилища не является защитой приватного ключа; защитой служат GitHub Secrets и права на локальный файл.

Обновление требует того же package ID и подписи. Ранее выпущенные APK имели одноразовые ключи; новый ключ не позволяет обновить их поверх. Не удалять старые приложения с данными и не обещать автоматический перенос. Отдельные «Библия · Проверка» и «Библия · Класс» имеют отдельные сессии. Постоянный ключ production release остаётся отдельной задачей.

Это проверка сохранения существующей Firebase-сессии, а не проверка новой формы Autofill или обновления между подписанными сборками. Реальные пароли/токены при проверке не читались и не сохранялись.
