## Решения пользователя (05.09.2026)

1. Администратор создаёт ведущих: новый аккаунт с ролью `leader` или назначение роли существующему пользователю.
2. Ведущий создаёт и изменяет свои классы. У одного ведущего может быть НЕСКОЛЬКО классов одновременно.
3. Ведущий добавляет зарегистрированных учеников либо приглашает новых по email (дополнение 06.09.2026); свободной самостоятельной записи нет.
4. У класса собственное время занятий, программа уроков и состав участников.
5. Администратор должен видеть дерево **ведущий → классы → ученики**. Оно размещено во вкладке «Ведущие и классы» админки.
6. Требуется аккуратная адаптивная верстка и постоянная доступность кнопки профиля при переходах между страницами.
7. Сохранять знания о проекте в этом `AGENTS.md`, обновлять его после существенных решений и завершения работ. Не сохранять секреты и реальные ответы учеников.

## Модель данных и права

- `users/{uid}`: `name`, `email`, `role` (`admin`, `leader`, `user`), необязательные `theme`, `created`.
- Только администратор меняет роли. Пользователь не может повысить свою роль даже при создании собственного профиля.
- `answers/{uid}_{lessonSlug}`: личные ответы `q*`, `_uid`, `_lesson`, `_savedAt`. Ведущий не получает доступ к личным ответам учеников.
- `classes/{id}`: `name`, `leaderUid`, `leaderName`, `weekday` (0 = воскресенье), `time` (HH:mm), `duration` (минуты), `startDate` (YYYY-MM-DD), `timezone` (`Europe/Moscow`), `place`, `description`, `lessonSlugs` (массив В ПОРЯДКЕ прохождения), `memberUids`, `archived`, `createdAt`, `updatedAt` (serverTimestamp).
- Встречи еженедельные по Москве; первая дата должна совпадать с выбранным днём недели. Ограничения: до 300 уроков, до 200 учеников в классе.
- `classAnswers/{classId}_{uid}_{lessonSlug}`: отдельные ответы класса с `_class`, `_uid`, `_lesson`, `_savedAt`, `q*`.
- Урок в классе открывается с `?class=ID`; личные ответы и ответы разных классов не смешиваются. Навигация предыдущий/следующий урок сохраняет класс и использует его программу.
- Ведущий управляет только своими классами и читает ответы своих классов. Для выбора состава ему доступен список профилей роли `user`.
- Ученик видит только классы, в которых состоит, и только свои ответы. Удаление из состава отзывает доступ. Архивный класс доступен для чтения, запись ответов запрещена.
- Администратор видит все классы и может переназначить действующего ведущего.
- Физическое удаление классов не реализовано: используется обратимое архивирование.
- Кнопка «Удалить профиль» удалена 06.09.2026: она оставляла аккаунт Auth и ссылки в классах. Не возвращать раздельное удаление профиля как управление аккаунтом. Для забытого пароля использовать письмо Firebase; для пропавшего профиля — восстановление с прежним UID.

## Восстановление аккаунтов (06.09.2026)

- Firebase Auth и `users/{uid}` — разные сущности. Удаление документа `users` не освобождает email. Пользователей нужно восстанавливать с исходным UID, чтобы сохранить членство и ответы.
- `BibleDB.resetPassword(email)` отправляет стандартное письмо Firebase. Пароль задаёт владелец email. Кнопки в админке и «Забыли пароль?» на странице входа. Не отправлять письмо при диагностике без согласия пользователя.
- Вместо удаления профиля в таблице пользователей — «Сбросить пароль». Общая кнопка «Восстановить доступ / профиль» открывает отправку письма: после входа отсутствующий профиль автоматически создаётся как ученик.
- Для потерянного участника дерева админки есть «Восстановить профиль»: UID берётся из членства, администратор указывает проверенные email и имя. Восстановление создаёт роль `user` транзакцией и отказывает, если профиль уже существует; классы и ответы не меняются. Перед ручным восстановлением сверять UID/email в Firebase Authentication.
- При частичном создании нового пользователя админка сохраняет UID до закрытия формы и повторяет только запись профиля. Если окно закрыто, использовать восстановление доступа.
- Полного удаления Firebase Auth из браузерной админки нет. Для него требуется доверенный backend/Admin SDK и согласованный порядок обработки классов/ответов; не имитировать его удалением Firestore-документа.
