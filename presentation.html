Проблема

Зачем нужна платформа?

  • Уроки в Word-документах — неудобно распространять и обновлять
  • Ответы учеников теряются в тетрадях и блокнотах
  • Ведущим сложно отслеживать прогресс группы
  • Нет единого места для всех материалов

Нужна простая платформа, где ученики читают уроки, отвечают на вопросы, а ведущие видят прогресс.

Организация занятий

Классы

  • Ведущий и состав учеников
  • День, время и длительность встречи
  • Первая дата и место встречи
  • Свой набор уроков
  • Порядок прохождения программы
  • Отдельные ответы каждого класса

Встречи еженедельные, время московское. Один ведущий может вести несколько классов одновременно.

Безопасность

Защита данных

  • Вход через Firebase Auth
  • Передача данных по HTTPS
  • Ученик видит только свои ответы
  • Ведущий читает ответы своих классов
  • Роли назначает администратор
  • Личные ответы закрыты от ведущего
  • Исключение из класса отзывает доступ
  • Архивный класс доступен для чтения

Доступ проверяют правила Firestore. Личные ответы и ответы разных классов хранятся отдельно.

Персонализация

Четыре темы оформления

Каждый ученик может выбрать удобный для себя визуальный стиль платформы. Выбор сохраняется в профиле и применяется на всех устройствах.

Классика
Тёмно-синий с золотым акцентом — спокойный и проверенный
Папирус
Журнальная типографика, кремовая бумага, винные акценты
Очаг
Тёплая палитра, мягкие карточки, неспешное чтение
Завет
Тёмная тема с янтарными акцентами — современно

Тема по умолчанию (для гостей) задаётся в _config.yml. Авторизованный ученик меняет тему в личном кабинете.

Масштабирование

Добавление новых курсов

Для добавления нового курса нужно:

  • Создать Markdown-файлы уроков в папке _lessons/
  • Создать страницу курса с фильтром по коллекции
  • Добавить карточку на страницу курсов

Каждый урок — отдельный Markdown-файл. Вопросы — HTML-блоки с textarea. Jekyll автоматически собирает всё при сборке сайта.

Эксплуатация

Хостинг и обновления

  • Рабочий адрес: learning.spbchurch.ru
  • Сайт размещён на сервере церкви и раздаётся через Nginx
  • Контент и код хранятся в Git; публикация после сборки Jekyll
  • Правила доступа Firebase публикуются отдельно от сайта
  • Перед обновлением сохраняется резервная копия сайта

Расходы зависят от серверной инфраструктуры и использования Firebase.
