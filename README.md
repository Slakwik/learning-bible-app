Этот репозиторий содержит предварительную нативную Android-версию проекта. Оригинальный веб-сайт и исходный проект: [Slakwik/bible-learning](https://github.com/Slakwik/bible-learning). Описание приложения, настройки, проверки и ограничения: [android/README.md](android/README.md).

## Исходный веб-проект

Веб-платформа для совместного изучения Священного Писания, построенная на Jekyll 4.4.1 + Firebase. Подходит для домашних групп, воскресных школ и индивидуального изучения.

Учебные материалы предоставлены МРО Санкт-Петербургский Центр «Духовное Возрождение» Евангельских Христиан-Баптистов.

## Возможности

### Для учеников
- **21 курс, 227 уроков** — от Бытия до Откровения: Ветхий Завет, Евангелия, послания и тематические курсы
- **Интерактивные вопросы** — отвечайте на вопросы прямо в уроке, ответы автосохраняются
- **Страница «Мои ответы»** — просмотр и печать всех своих ответов по курсу
- **Отслеживание прогресса** — пройденные уроки отмечаются в списке
- **Кнопка «Подать заявку»** — форма записи для новых учеников (видна только неавторизованным)

### Для администраторов
- **Управление пользователями** — добавление, редактирование, удаление учеников через админку
- **Просмотр прогресса** — ответы каждого ученика по всем урокам
- **Статистика уроков** — сколько учеников прошли каждый урок

### Общее
- **Лендинг** с цитатой из Писания, карточками курсов и формой записи
- **Страница «О курсе»** — презентации (PDF и HTML), описание платформы
- **Доступ к урокам** — список уроков виден всем, содержимое — только после входа
- **Адаптивный дизайн** — работает на десктопе и мобильных устройствах

## Firebase

Проект использует Firebase для авторизации и хранения данных.

### Коллекции Firestore

| Коллекция | Документ | Поля |
|-----------|----------|------|
| `users` | `{uid}` | `name`, `email`, `role`, `created` |
| `answers` | `{uid}_{lessonSlug}` | `q1`, `q2`, ... , `_uid`, `_lesson`, `_savedAt` |

### Настройка Firebase

1. Создайте проект на [console.firebase.google.com](https://console.firebase.google.com)
2. Создайте веб-приложение и скопируйте конфиг в `assets/js/firebase-app.js`
3. **Authentication** → включите провайдер **Email/Password**
4. **Firestore Database** → создайте базу данных
5. **Firestore → Rules** → вставьте содержимое `firestore.rules` и нажмите **Publish**. Тестовый режим с датой окончания для рабочего сайта не подходит.

Правила публикуются отдельно от Jekyll: обновление файлов на сервере само по себе не меняет настройки Firebase. Альтернатива консоли после авторизации Firebase CLI:

```bash
firebase deploy --only firestore:rules --project bible-learning-b4b4d
```

Ученики читают свой профиль и свои ответы; администраторы управляют профилями и просматривают ответы. Ученик не может назначить себе роль администратора. Кнопка «Удалить профиль» не удаляет аккаунт Firebase Authentication и ответы. Полное удаление аккаунта выполняется в Firebase Console.

Проверки JavaScript (Node.js 22+):

```bash
node --test tests/*.test.cjs
```

### Создание первого администратора

1. **Authentication → Add user** — создайте пользователя с email и паролем
2. **Firestore → `users`** — создайте документ с ID = UID пользователя:
   ```
   name: "Администратор"
   email: "admin@example.com"
   role: "admin"
   ```
3. Войдите на сайт — в навигации появится ссылка «Админка»
4. Новых учеников добавляйте через админку (`/admin/`)

## Android-приложение

Нативное Kotlin-приложение находится в `android/`. Уроки включаются в APK для чтения без интернета. Личные ответы сохраняются в SQLite отдельно для каждого UID; гостевые черновики не отправляются. Синхронизация запускается вручную в настройках или автоматически, если включить её. Конфликты одного поля не перезаписываются без выбора пользователя. Подробности и ограничения — в `android/README.md`.

Для сборки нужен JDK 17 и Android SDK 35:

```bash
cd android
gradle testDebugUnitTest lintDebug assembleDebug
```

Тестовый APK появится в `android/app/build/outputs/apk/debug/app-debug.apk`. GitHub Actions проверяет проект при push в main, PR и ручном запуске. Для публикации подписанного предварительного релиза по тегу `v*` нужны отдельные секреты подписи; debug APK не используется как обновляемый релиз.

## Адаптация под свою церковь

Если вы хотите использовать эту платформу в своей церкви, вот что нужно изменить:

### Обязательно

| Что | Где | Что поменять |
|-----|-----|-------------|
| Название церкви и ВН | `_includes/footer.html` | Замените «Церковь Преображение» и номер ВН на свои |
| Конфиг Firebase | `assets/js/firebase-app.js` | Создайте свой проект Firebase и вставьте свой `firebaseConfig` |
| Форма записи | `signup.html` | Замените ссылку на Яндекс-форму на свою или создайте свою форму |
| Фон лендинга | `assets/img/hero-bg.jpeg` | Замените на фото вашей церкви или подходящее изображение |

### По желанию

| Что | Где | Что поменять |
|-----|-----|-------------|
| Название сайта | `_config.yml` | Поле `title` |
| Цветовая схема | `assets/css/style.css` | CSS-переменные в `:root` — `--primary`, `--accent` и др. |
| Цитата на главной | `index.html` | Блок `hero-verse` — текст и ссылка на стих |
| Текст на лендинге | `index.html` | Заголовок, описание, карточки возможностей |
| Страница «О курсе» | `about.html` | Информация о материалах, ссылка на организацию |
| Правила Firestore | `firestore.rules` | При необходимости — настройте правила доступа |
| Презентации | `presentation.html`, `presentation.pdf` | Обновите под свою церковь и курсы |

### Порядок действий

1. **Форкните** этот репозиторий
2. Создайте **свой проект Firebase** и вставьте конфиг
3. Замените **название церкви** в footer и на странице «О курсе»
4. Замените **форму записи** и **фон лендинга**
5. При необходимости скорректируйте **цветовую схему**
6. Разверните сайт (GitHub Pages, Netlify, или свой сервер)
7. Создайте **первого администратора** в Firebase (см. раздел выше)

Уроки и курсы можно использовать как есть — они не привязаны к конкретной церкви.

## Классы и ведущие

- Администратор создаёт аккаунт с ролью «Ведущий» или назначает эту роль существующему пользователю в админке.
- Ведущий открывает `/classes/`, создаёт класс и добавляет зарегистрированных учеников. Он управляет только своими классами; администратор может управлять всеми и менять ведущего.
- У класса есть название, день недели, время начала по Москве, длительность, дата первой встречи, место, описание и упорядоченный набор уроков из любых курсов.
- Ученики видят только классы, в которые их добавили. Ссылки на уроки класса содержат `?class=ID`.
- Ответы класса хранятся отдельно от личных ответов. Ведущий видит ответы своего класса, но не личные ответы учеников. После удаления из состава ученик теряет доступ к классу и его ответам; данные сохраняются для ведущего.
- Архивирование класса сохраняет данные и запрещает новые ответы. Чтобы возобновить занятия, снимите флажок архива.

Коллекции Firestore: `classes/{id}` (ведущий, расписание, `lessonSlugs`, `memberUids`) и `classAnswers/{classId}_{uid}_{lessonSlug}` (ответы с `_class`, `_uid`, `_lesson`). Старые `users` и `answers` сохраняются. Для запуска раздела нужно опубликовать обновлённый `firestore.rules`, а затем собрать Jekyll.

### Проверка прав доступа

Нужны Node.js 22+ и Java 21+. Эмулятор использует только тестовый проект `demo-bible-classes` и не обращается к рабочей базе.

```bash
npm ci
npm test
npm run test:rules
```

Тесты проверяют назначение ведущих, создание и изменение своих классов, запрет изменения чужих классов, состав участников, запросы списков, изоляцию ответов, архивирование и отзыв прав.

PDF пересобирается командой `python3 gen_presentation.py` (ReportLab и шрифты с кириллицей). При обновлении презентаций согласованно менять HTML, генератор PDF и описания в `about.html`.


### Объявления и приглашения

Общие объявления публикует администратор на `/announcements/`. Они видны после входа на главной странице и в классах. Ведущий публикует объявления своего класса в его карточке. Объявления можно редактировать и архивировать.

В карточке класса ведущий указывает имя и email ученика и нажимает «Отправить приглашение». Ученик открывает письмо, вводит свой email и самостоятельно задаёт пароль. Приглашение действует 7 дней; его можно отозвать или отправить повторно. Существующие аккаунты сохраняют прежний UID и ответы.

Firebase Authentication должен разрешать Email link sign-in, а домен сайта — находиться в Authorized domains. На Spark доступно до 5 писем-приглашений в день на проект. Для проверки без реальной рассылки: `npm run test:invitations` (Java 21+, Auth и Firestore Emulator).

## Доступ к курсам (0.3.1-preview)

Без авторизации доступны только названия и описания курсов. После входа каталог показывает вводный текст урока до первого вопроса, без вопросов и ответов. Полные уроки и работа с ответами доступны только в классе; ведущие сохраняют просмотр своих учеников. Синхронизация отправляет только ответы классов. Старые личные и гостевые записи остаются в локальном хранилище и экспорте, автоматически в классы не переносятся.
